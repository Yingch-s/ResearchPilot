# ResearchPilot

ResearchPilot 是一个本地优先的研究工作台。你可以把自己的 PDF、Markdown、TXT、图片等资料放进研究专题，用自然语言提问；需要更完整的调研时，系统会先给出研究计划，执行过程中展示检索方向和来源进展，最后生成一份可以继续编辑和引用的 Markdown 研究报告。

它适合需要反复阅读资料、比较观点、追踪来源和沉淀研究结果的工作。资料、对话和报告都属于同一个研究专题，回答不会脱离当前专题的资料范围。

## 快速启动

需要安装 Docker Desktop，并为 Docker 分配足够的内存和磁盘空间。第一次启动会下载 Java、Python 依赖和本地解析/向量模型，首次启动时间会比较长。

```powershell
Copy-Item .env.example .env
docker compose -f compose.yaml up --build -d
```

打开 <http://localhost:5174>。

启动后进入右上角的“设置”，填写模型 API 地址、模型名称和模型 Key。需要联网补充来源时，再填写 Tavily API Key。设置页只显示密钥掩码，不会回显完整密钥。

保存设置后重启后端：

```powershell
docker compose -f compose.yaml restart backend
```

## 第一次使用

1. 创建一个研究专题。
2. 添加 PDF、Markdown、TXT 或图片资料，等待资料可以被阅读。
3. 在左侧选择本次回答要使用的资料。
4. 在输入框中直接提问。
5. 需要即时回答时保持“深度研究”关闭；需要完整研究报告时勾选“深度研究”。

快速提问和深度研究使用同一个对话。深度研究不是另一个页面，而是同一个问题输入框的另一种处理方式。

## 快速提问和深度研究

快速提问适合确认事实、解释概念、定位原文和比较资料中的内容。系统会直接返回回答，并在真正使用资料的位置附上引用。

深度研究适合范围更大、需要多步核查的问题。流程是：

```text
提出问题
   ↓
生成简短研究计划
   ↓
用户确认或调整计划
   ↓
按步骤检索资料、必要时搜索网页
   ↓
展示当前研究方向和来源进展
   ↓
生成 Markdown 研究报告
   ↓
自动保存到左侧“研究报告”分类
```

研究运行期间可以暂停、恢复或停止。页面刷新后，已保存的研究状态可以继续查看。

## 系统如何理解一个问题

ResearchPilot 会先判断问题属于哪一类：闲聊、通用知识、资料问答，还是在资料中查找具体位置。这个判断用于选择回答方式和检索范围：闲聊不会无意义地触发资料检索；资料问题会限制在当前专题和选中的资料中；定位问题会优先寻找章节、摘要和原文位置。

这个分类是路由信息，不会替用户决定研究目标。用户在界面上选择的资料范围、联网搜索和深度研究模式具有更高优先级。

## 上下文、记忆和内容范围

模型不会在每次提问时读取整个资料库和全部历史对话。系统会按当前问题装配一份有预算的上下文，通常包含：

- 当前问题和最近几轮对话；
- 当前研究专题的长期记忆；
- 用户偏好，例如语言和回答习惯；
- 当前会话的摘要；
- 从资料库检索出的相关片段；
- 深度研究已经确认的结论和来源；
- 用户明确允许使用的网页来源。

这些内容有不同的保存范围：用户偏好可以跨专题使用，专题记忆属于一个研究专题，会话摘要属于一条对话，研究证据属于一次研究任务。对话过长时，系统会压缩较早的消息，保留摘要、最近对话和重要来源，避免上下文无限增长。

资料范围始终由专题和用户选中的资料共同限制。模型只会看到本轮装配的片段，不会因为语义相似而自动读取其他专题的资料。

## RAG 检索如何工作

资料检索同时使用关键词和语义相似度：

```text
关键词检索（BM25） ─┐
                    ├─ 排名融合 → 章节补充 → 上下文预算 → 回答
向量检索（Dense） ──┘
```

关键词检索适合论文标题、方法名、精确术语和数字；向量检索适合近义表达、改写问题和跨语言提问。两路结果会通过排名融合合并，再根据资料范围、章节类型和相关性进行筛选。命中的片段必要时会扩展到所属章节，避免模型只看到孤立的一句话。

检索结果只是候选内容，不会自动被当成事实。回答阶段还会检查引用是否能支持对应陈述；找不到足够依据时，系统会说明资料不足，而不是把未检索到的内容说成原文结论。

## 联网搜索和引用

开启“联网搜索”后，系统会在本地资料之外补充网页来源。网页来源会单独标识，并保留网站名称、页面标题和 URL。回答中的网页引用不会伪装成本地论文引用，报告中也会保留对应链接。

联网搜索适合补充最新信息、查找专题资料中没有覆盖的背景，不能替代用户自己的资料范围。关闭联网搜索时，回答不会因为资料命中不足而偷偷访问网页。

## 深度研究中的多 Agent 协同

深度研究会先把问题拆成多个可验证的研究步骤，例如资料定位、方法分析、结果比较和来源复核。每个步骤由一个有明确目标、资料范围、调用次数和时间预算的研究 Worker 执行，最后由研究调度器合并结果并生成报告。

```text
研究计划
   ├─ 资料检索
   ├─ 网页补充
   ├─ 方法分析
   ├─ 结果比较
   └─ 证据复核
          ↓
     结果合并与冲突检查
          ↓
       研究报告
```

Worker 不能无限递归地创建其他 Worker。每个步骤都有预算、截止时间和取消信号，部分步骤失败时仍会保留可以确认的结果，并把未完成部分写入报告限制。这样深度研究更像一个受控的研究流程，而不是多个模型无边界地互相调用。

## 报告和资料库

深度研究生成的是 Markdown 报告。报告会包含研究问题、主要结论、来源和限制，并自动保存到左侧的“研究报告”分类。

报告可以像普通资料一样继续阅读、参与后续检索，也可以在新的对话中被引用。资料库中的论文、网页快照和研究报告使用统一的来源模型，便于在同一个专题里继续研究。

## 配置和数据

`.env` 适合部署时配置基础服务和初始环境变量：

```text
LLM_API_KEY       模型 API Key
LLM_BASE_URL      OpenAI 兼容模型地址
LLM_MODEL         模型名称
TAVILY_API_KEY    联网搜索 Key
POSTGRES_PASSWORD 数据库密码
```

日常配置优先使用网页“设置”。网页保存的模型地址、模型名和 Key 会写入后端数据卷中的运行配置文件，不会写进源码或 README。模型客户端在后端启动时创建，因此修改模型配置后需要重启 backend。

专题、资料、会话和报告保存在 Docker volume 中。迁移或备份时，应同时保留数据库卷、后端数据卷和 Elasticsearch 数据卷。

## 常见问题

**页面能打开，但模型没有回答？** 进入“设置”检查模型 API 地址、模型名和 Key，然后重启 backend。

**联网搜索没有来源？** 检查 Tavily Key 是否已配置，并确认当前输入框旁的“联网搜索”已开启。

**第一次启动为什么很慢？** Python sidecar 会安装文档解析依赖，并首次下载本地 embedding 模型。后续启动会使用 Docker volume 中的缓存。

**如何停止服务？**

```powershell
docker compose -f compose.yaml down
```

**如何清空所有数据？** 以下命令会删除专题、资料、会话和报告：

```powershell
docker compose -f compose.yaml down -v
```

## 评测结果

所有评测脚本、原始数据与分析报告位于 `evaluation/`。语料与协议已在各报告中披露，数字可复现。

### 检索（LitSearch，597 查询，成对统计检验）

| 通道 | R@5 | R@10 | MRR@10 | nDCG@10 |
|---|---|---|---|---|
| BM25 | 59.97% | 66.16% | 0.491 | 0.525 |
| Dense（BGE-M3） | 68.17% | 73.87% | 0.548 | 0.586 |
| **Hybrid+RRF** | **69.51%** | **76.38%** | **0.582** | **0.619** |

Hybrid 优于 BM25 达 p≈3.2e-10，优于 Dense 达 p≈0.049（McNemar 成对检验）。

### 证据可信度（SciFact，1,108 条声明）

| 指标 | 数值 |
|---|---|
| 假支持率（证据不足时误判“支持”） | **4.0%** |
| SUPPORT 判对 | 82.2% |
| 纯相关度规则 vs LLM 判定 | 63.0% vs 91.5%（embedding 不能替代语义判定） |
| 判定管线 vs 独立二次判定一致率 | **95.0%**（57/60，边界 case 逐条留档） |

### 端到端（12 任务 × Full/Basic/B0 × 3 轮，Ground Truth 独立核验）

| 指标 | Full（深度研究） | Basic RAG | B0（无知识库） |
|---|---|---|---|
| 矩阵覆盖率 | 0.593 | 0.384 | 0.722 |
| 无依据断言 | **17**（0.47/报告） | 0 | 45（1.25/报告） |
| 编造报告 | **0 / 36** | 0 / 36 | 6 / 36 |
| 负例正确率（资料中没有的问题） | 9/9 诚实表达未找到 | 9/9 | 9/9 |

B0 靠参数知识覆盖率最高，但代价是 45 条无依据断言与 6 份含编造的报告；Full 覆盖率略低，但零编造、每条结论挂证据引用、全程可溯源。

### 跨语言检索（中文查询检索英文论文）

| 方案 | R@10 | 相对英文上界保持率 |
|---|---|---|
| 中文直查（Dense） | 0.38 | 50.0% |
| **中文 + 查询翻译前置** | **0.68** | **89.5%** |
| 英文上界（Dense） | 0.76 | 100% |

### 检索性能（5,574 chunks，与生成完全分离）

| 通道 | P50 | P95 | QPS（50 并发） |
|---|---|---|---|
| Hybrid+RRF | 163ms | 581ms | 13.6（零错误） |

### 成本

深度研究全管道 ≈ **¥0.38/任务**（DeepSeek 官方价）；快速提问 ≈ ¥0.006/次。成本与产出对比：Full 用约 127 倍于 B0 的成本换来了证据溯源、双层引用校验与零编造。

## 架构

### 技术栈

Java 17 / Spring Boot 3.4 / Spring AI —— 后端单体；PostgreSQL（状态与元数据）+ Elasticsearch（检索）；Python sidecar（Docling 解析 + BGE-M3 向量）；Vue 3 前端。

### 检索与证据链路

```text
PDF/MD/TXT → Docling 解析 → 结构化切分 → BM25 + BGE-M3 Dense 双通道
    → RRF 融合 → 章节补充（Parent 扩展）→ 上下文预算
    → 生成 → 双层引用校验（确定性引文比对 + LLM 语义判定）
    → 独立存储 quote_status / claim_status → 报告
```

### 任务调度与可靠性

```text
CREATED → PLANNING → WAITING_APPROVAL → RESEARCHING → VERIFYING → FINALIZING
            │              │                │                        ├── COMPLETED
            │              │                │                        ├── PARTIAL_COMPLETED（诚实停止+披露）
            │              │                │                        └── FAILED
            └──────────────┴──→ QUEUED ────┘（准入队列，FIFO 补位）
                                   └──→ CANCELLED
```

- 状态机单点条件转移（`UPDATE ... WHERE status = from`），乐观并发无双调度
- Run 级租约 + 心跳 + 恢复扫描：worker 崩溃后任务可被任意健康实例接管
- attempt 幂等键：旧执行段的迟到提交被条件更新拒绝
- 全局准入：pg advisory lock 串行化准入决策，队列满返回 429 + Retry-After
- 三段 Deadline：全局预算 → 研究截止 → 终稿保留，预算耗尽诚实收敛为 PARTIAL 并披露未完成项

## 工程亮点

- **并发不超限**：advisory lock 串行化准入决策，10 线程并发测试活跃数恒 ≤ 上限（`RpAdmissionServiceIT`）
- **多用户数据隔离**：归属过滤统一在 Service 层，越权一律 404 不泄露存在性，17 端点越权矩阵测试（`RpOwnershipIT`）
- **跨语言检索修复闭环**：量化中文直查退化（保持率 47%）→ 定位 BM25 噪声与语义鸿沟 → 查询翻译前置 + 失败降级 → 保持率 89.5%，前后对照可复现
- **LLM 韧性**：429/503 指数退避（限流先重试后降级）；登录限速；检索缓存防穿透
- **故障演练**：worker 死亡接管、LLM 全挂快速失败、DB 瞬断手册（`docs/chaos/`）
- **评测器自校准**：独立二次判定 95% 一致率 + 分歧逐条留档——评测系统本身也被评测
