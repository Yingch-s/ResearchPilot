# E2 · b0 · round 3

ANCE 如何刷新全局难负例所用的 ANN 索引？

---

在 ANCE（Approximate Nearest Neighbor Negative Contrastive Estimation）里，**全局难负例**是从整个语料库中按当前模型打分选出的高难度负例；为了高效地从全库中找这些负例，需要用一个 **ANN 索引**来近似最近邻搜索。ANCE 对这个 ANN 索引的刷新方式，核心可以概括为：

**它不是每步都重建，而是按一定训练步数间隔，用当前（或近期）的查询/文档编码器重新编码语料并重建/更新 ANN 索引；在两次刷新之间，索引保持不变，继续用于采样全局难负例。**

下面按对象拆开说明。

## 1. 为什么需要刷新 ANN 索引

ANCE 的负例不是固定的，而是随着模型训练不断变化的：

- 训练初期，模型还不好，它认为“难”的负例和后期不同；
- 训练后期，模型变强，原来难的负例可能已经不难，需要从全库中重新找更难的负例；
- 如果 ANN 索引一直不更新，它反映的是旧模型下的表示空间，采样出的“全局难负例”会逐渐失真。

所以 ANCE 必须让 ANN 索引跟上模型表示的变化。

## 2. 刷新的基本对象

涉及几个对象：

1. **查询编码器 / 文档编码器**：通常共享或联合训练，用来把 query 和 passage 映射到同一向量空间。
2. **语料库文档向量**：全库 passage 的向量表示。
3. **ANN 索引**：建立在文档向量上的近似最近邻结构，例如 FAISS 索引。
4. **全局难负例采样过程**：对每个 query，用 ANN 在文档向量中找 top-k 近似最近邻，再从中选负例。
5. **训练步 / checkpoint**：刷新发生的时机。

ANCE 刷新的是第 3 个对象，但刷新它需要先用第 1 个对象重新计算第 2 个对象。

## 3. 刷新流程（典型做法）

典型 ANCE 训练循环可以理解为：

1. 用当前模型编码一批 query。
2. 对每个 query，用当前 ANN 索引检索全库，得到一批候选文档。
3. 从候选中选出全局难负例，和正例一起计算对比损失。
4. 反向传播更新 query/document 编码器。
5. 每隔若干训练步（例如每 N 步、每个 epoch，或按 warm-up 后的某个频率）：
   - 用**当前文档编码器**重新编码整个语料库；
   - 用新的文档向量**重建 ANN 索引**；
   - 后续采样改用新索引。
6. 在两次刷新之间，ANN 索引冻结，不随每步参数更新而变。

也就是说，刷新是**周期性、异步于参数更新**的，而不是每步同步重建。

## 4. 刷新频率与策略

ANCE 论文中通常不是每一步都刷新，因为全库编码和建索引代价很高。常见策略包括：

- **按固定步数间隔刷新**：例如每若干千步或每个 epoch 刷新一次；
- **warm-up 后再启用全局难负例**：训练最开始可能先用 in-batch 负例或随机负例，等模型有一定基础后再启用 ANN 全局负例；
- **异步刷新**：有些实现会用单独的进程/线程定期用最新 checkpoint 重建索引，训练进程继续用旧索引采样，等新索引准备好后切换。

具体频率在 ANCE 原论文和不同复现中不完全一致，我无法凭记忆给出一个唯一确定的“官方固定值”。如果你需要精确数字，建议查原论文实验设置或官方代码中的 `refresh_interval` / `ann_refresh` 之类参数。

## 5. 刷新时用哪个模型

关键点：**用当前或近期的文档编码器**来重新编码全库。

- 如果严格同步，就用当前 step 的编码器；
- 如果异步，可能用最近一个 checkpoint 的编码器；
- 由于 query 和 document 编码器通常联合训练，刷新后的文档向量空间应与当前 query 编码器尽量一致。

如果两者偏差太大，ANN 检索出的“最近邻”就不再是当前模型眼中的难负例。

## 6. 与“局部难负例”的区别

ANCE 里有两类负例：

- **局部难负例 / in-batch 难负例**：来自同一 batch 内其他 query 的正例文档，不需要 ANN 索引，每步都能随 batch 变化。
- **全局难负例**：来自整个语料库，需要 ANN 索引从全库中检索。

刷新 ANN 索引主要影响的是**全局难负例**。局部难负例不依赖这个索引。

## 7. 一个容易混淆的点

“刷新 ANN 索引”不等于“重新训练模型”，也不等于“每步更新索引”。它是：

> 用当前编码器重新生成全库文档向量 → 重建 ANN 结构 → 让后续全局负例采样反映当前模型。

在两次刷新之间，模型参数仍在每步更新，但索引是旧的。这带来一定滞后，但换来了可接受的计算成本。

## 8. 不确定的地方

以下细节我无法保证对所有 ANCE 变体都成立：

- 原论文中确切的刷新步数/epoch 频率；
- 是否每次刷新都全量重建，还是增量更新；
- 异步刷新时具体用哪个 checkpoint；
- 不同复现（如 OpenMatch、Tevatron 等）的实现差异。

这些取决于具体论文版本和代码实现。如果你要写进研究笔记，建议标注“典型实现如此，具体频率以原论文/代码为准”。

## 一句话总结

ANCE 通过**周期性用当前文档编码器重新编码全库并重建 ANN 索引**来刷新全局难负例所用的索引；两次刷新之间索引冻结，训练继续，从而在计算成本和负例质量之间取得平衡。
