# A1 · b0 · round 3

DPR、ColBERT、ANCE、RocketQA 四篇论文各自提出的检索/建模核心方法是什么？

---

这四篇工作都属于“稠密检索/神经检索”方向，但各自的核心贡献不同。下面按论文分别说明。

## 1. DPR（Dense Passage Retrieval for Open-Domain Question Answering, 2020）

**核心方法：双塔（dual-encoder）稠密检索。**

- 用两个独立的 BERT 编码器分别把问题和段落编码成稠密向量：
  - 问题编码器 \(E_Q(q)\)
  - 段落编码器 \(E_P(p)\)
- 检索时用向量内积（或余弦相似度）作为相关性分数：
  \[
  \text{sim}(q,p)=E_Q(q)^\top E_P(p)
  \]
- 训练目标是对比学习/负采样：让正段落的分数高于负段落。常用 in-batch negatives，并配合若干“难负例”。
- 关键意义：证明了一个简单的双塔稠密检索器，在开放域问答检索上可以显著超过传统稀疏检索（如 BM25），并且检索可以用最大内积搜索（MIPS）高效近似实现。

**一句话：DPR 的核心是“双编码器 + 内积相似度 + 对比学习”的稠密段落检索。**

---

## 2. ColBERT（ColBERT: Efficient and Effective Passage Search via Contextualized Late Interaction over BERT, 2020）

**核心方法：延迟交互（late interaction）与 MaxSim 多向量匹配。**

- 不把整个查询/段落压成单个向量，而是保留每个 token 的上下文向量：
  - 查询编码为多个 token 向量
  - 段落编码为多个 token 向量
- 相关性分数用 **MaxSim**：
  - 对查询中每个 token，找它在段落中最相似的 token 向量；
  - 把这些最大相似度求和。
  \[
  S(q,d)=\sum_{i \in q}\max_{j \in d} E_q(i)^\top E_d(j)
  \]
- 这种“先分别编码、后做细粒度交互”的方式称为 **late interaction**，介于双塔（无交互）和交叉编码器（早交互）之间。
- 工程上还提出用向量压缩/剪枝等策略降低存储和延迟。

**一句话：ColBERT 的核心是“保留 token 级多向量表示 + MaxSim 延迟交互”的检索模型。**

---

## 3. ANCE（Approximate Nearest Neighbor Negative Contrastive Learning for Dense Text Retrieval, 2021）

**核心方法：用近似最近邻（ANN）检索出的负例来做对比学习。**

- DPR 类双塔检索器训练时，负例通常来自 in-batch negatives 或固定语料随机采样。ANCE 指出：训练时看到的负例分布和推理时全语料检索得到的分布不一致，导致训练/推理不匹配。
- ANCE 的做法：
  - 周期性地用当前模型对全语料做 ANN 检索；
  - 把检索到的高分但非正例的文档作为“难负例”；
  - 用这些负例继续训练检索器。
- 这相当于让负例来自模型当前认为最像正例的文档，从而缓解“训练负例太简单”的问题。
- 它强调负例采样分布应与推理时的候选分布接近。

**一句话：ANCE 的核心是“用 ANN 动态检索难负例”的对比学习训练策略，而不是提出全新的网络结构。**

---

## 4. RocketQA（RocketQA: An Optimized Training Approach for Dense Passage Retrieval, 2021）

**核心方法：面向稠密段落检索的系统化训练优化，主要针对数据噪声、负例和跨设备大 batch 问题。**

RocketQA 通常被概括为几个关键点：

1. **跨 batch 负例（cross-batch negatives）**
   - 在多 GPU 训练时，不仅用本 GPU batch 内的负例，还聚合其他 GPU 的负例，扩大负例数量，提升对比学习效果。

2. **去噪训练（denoised training）**
   - 针对训练数据中“假正例/未标注正例”问题：有些段落其实相关但被当作负例。
   - 用教师模型或交叉编码器过滤掉可能相关的“伪负例”，减少噪声。

3. **数据增强/伪标签**
   - 用强检索器或交叉编码器挖掘未标注段落，扩充正例，缓解标注不足。

整体上，RocketQA 不是单纯提出一个新的相似度结构，而是提出一套训练流程，使双塔稠密检索器在开放域问答等任务上更强。

**一句话：RocketQA 的核心是“跨 batch 负例 + 去噪 + 数据增强”的稠密检索训练优化方案。**

---

## 对比总结

| 论文 | 核心方法 | 主要创新层面 |
|---|---|---|
| DPR | 双塔 BERT 编码器 + 内积 + 对比学习 | 模型框架/稠密检索范式 |
| ColBERT | token 级多向量 + MaxSim 延迟交互 | 匹配结构与交互方式 |
| ANCE | 用 ANN 动态挖掘难负例 | 负例采样/训练策略 |
| RocketQA | 跨 batch 负例、去噪、数据增强 | 训练流程与数据优化 |

如果用一个更简化的线索串起来：

- **DPR**：把检索变成双塔向量内积。
- **ColBERT**：觉得单向量太粗，改成多向量延迟交互。
- **ANCE**：觉得负例太简单，改成 ANN 动态难负例。
- **RocketQA**：觉得训练数据和负例都有噪声/不足，改成跨 batch、去噪、增强的一整套训练方案。
