梳理从 DPR 到 RocketQA 负样本策略的演进主线，覆盖全部四篇论文。

下面按“从 DPR 到 RocketQA”的时间与问题演进主线，梳理四篇论文中负样本策略的变化。这里说的“四篇论文”通常指：

1. **DPR**：Karpukhin et al., 2020, *Dense Passage Retrieval for Open-Domain Question Answering*
2. **ANCE**：Xiong et al., 2021, *Approximate Nearest Neighbor Negative Contrastive Learning for Dense Text Retrieval*
3. **RocketQA 前身/相关的一篇常被放入主线的是 RocketQA 的检索器训练论文**：Qu et al., 2021, *RocketQA: An Optimized Training Approach to Dense Passage Retrieval for Open-Domain Question Answering*
4. **RocketQA v2 / RocketQAv2**：Ren et al., 2021, *RocketQAv2: A Joint Training Method for Dense Passage Retrieval and Passage Re-ranking*

不过需要先说明一个不确定点：如果你说的“四篇论文”有固定课程/综述指定列表，可能不是上述四篇，也可能把 **DPR、ANCE、RocketQA、RocketQAv2** 作为主线；也可能把 **DPR、ANCE、RocketQA、RocketQAv2** 中的 RocketQA 与 RocketQAv2 合并/拆分方式不同。下面我按最自然的四篇主线来回答，并明确标注不确定处。

---

## 一、总体演进主线

从 DPR 到 RocketQA/RocketQAv2，负样本策略的核心演进可以概括为：

> **随机/批内负样本 → 难负样本挖掘 → 动态难负样本 → 去噪难负样本 + 跨批次/跨模型联合训练**

更具体地说：

1. **DPR**：主要使用 **in-batch negatives**，即同一个 batch 中其他问题的正段落作为当前问题的负样本；辅以少量 BM25 难负样本。  
2. **ANCE**：指出 in-batch negatives 与真实检索分布不一致，提出 **ANCE**，用近似最近邻索引动态挖掘全局难负样本，并异步更新索引。  
3. **RocketQA**：指出难负样本会带来 **假阴性** 问题，提出 **cross-batch negatives**、**denoised negatives**，并采用“检索器-重排器”联合/迭代训练来筛选更可靠负样本。  
4. **RocketQAv2**：进一步把检索器和重排器做 **联合训练**，用重排器给检索器提供更细粒度的软标签/去噪信号，负样本策略从“静态挖掘”走向“动态、去噪、联合优化”。

---

## 二、DPR：以 in-batch negatives 为主，辅以 BM25 难负样本

### 1. 背景
DPR 的目标是训练一个双塔密集检索器：  
- 问题编码器 \(E_Q(q)\)
- 段落编码器 \(E_P(p)\)
- 用内积或余弦相似度检索。

训练目标是让正段落 \(p^+\) 的得分高于负段落 \(p^-\)。

### 2. 负样本策略
DPR 论文中主要采用：

- **In-batch negatives**：  
  对一个 batch 中的 \(B\) 个问题-正段落对，把其他问题的正段落当作当前问题的负样本。  
  这样每个问题有 \(B-1\) 个负样本，计算效率高。

- **BM25 难负样本**：  
  对每个问题，用 BM25 检索出与问题词面匹配但可能不是答案的段落，作为额外难负样本。  
  DPR 论文中通常每个问题加入少量 BM25 负样本，例如 1 个或若干個。具体数量我记不精确，常见描述是“每个问题加入一个 BM25 负样本”或“少量 BM25 负样本”，这里不确定具体超参。

### 3. 局限
- In-batch negatives 与真实检索候选分布差异大：batch 内负样本通常来自其他问题，和当前问题可能语义不相关，因此太“容易”。
- BM25 难负样本虽然更难，但数量有限，且词面匹配不等于语义难。
- 没有动态更新负样本，训练前期和后期负样本难度不变。

### 4. 在主线中的位置
DPR 奠定了“双塔密集检索 + in-batch negatives”的基础范式，但负样本策略较简单，成为后续 ANCE 和 RocketQA 改进的起点。

## 三、ANCE：动态全局难负样本，解决 in-batch negatives 分布不一致

### 1. 核心问题
ANCE 论文指出：  
- 如果只用 in-batch negatives，负样本来自当前 batch 的其他正段落，其分布与真实检索时从全库中召回的候选分布不一致。
- 真实检索中，负样本往往是与问题语义相近、但并非答案的“难负样本”。
- 因此需要从**全局语料库**中挖掘难负样本。

### 2. 负样本策略
ANCE 提出 **Approximate Nearest Neighbor Negative Contrastive Learning**：

- 使用当前检索器对全库建立 **ANN 索引**。
- 对每个训练问题，用 ANN 检索出 top-k 段落作为候选。
- 其中排除正段落，剩下的作为难负样本。
- 由于全库 ANN 检索开销大，ANCE 采用 **异步更新索引**：  
  检索器参数更新后，索引不是每步重建，而是定期/异步刷新。
- 训练目标是对比学习：正样本得分高，ANN 难负样本得分低。

### 3. 与 DPR 的区别
| 方面 | DPR | ANCE |
|---|---|---|
| 负样本来源 | batch 内其他正段落 + BM25 | 全局 ANN 检索 top-k |
| 难度 | 较容易/静态 | 动态难负样本 |
| 分布 | 与真实检索分布不一致 | 更接近真实检索分布 |
| 更新 | 固定 | 异步更新索引 |
| 问题 | 假阴性较少但负样本太易 | 难负样本可能含假阴性 |

### 4. 局限
- ANN 难负样本中可能包含**假阴性**：即实际上能回答问题的段落，但被当作负样本。
- 假阴性会误导训练，尤其当 top-k 中很多段落与问题相关但未被标注为正例时。
- 索引异步更新带来工程复杂性和训练不稳定。

### 5. 在主线中的位置
ANCE 把负样本从“batch 内”推进到“全局动态难负样本”，是 DPR 之后的关键一步。但它没有很好解决假阴性问题，这成为 RocketQA 的切入点。

## 四、RocketQA：去噪难负样本 + cross-batch negatives + 检索器-重排器迭代

### 1. 核心问题
RocketQA 论文关注两个问题：

1. **难负样本中的假阴性**：  
   ANCE 式难负样本可能包含真正相关段落，直接当负样本会伤害训练。
2. **in-batch negatives 的 batch 规模限制**：  
   单卡 batch 有限，负样本数量不足；跨卡/跨批次负样本可以利用更多负例。

### 2. 负样本策略
RocketQA 的主要策略包括：

- **Cross-batch negatives**：  
  不只使用当前 GPU/当前 batch 内的负样本，而是跨多个 batch 或跨 GPU 收集负样本，扩大负样本池。  
  这样可以在不增加单卡内存太多的情况下增加负样本数量。

- **Denoised negatives / 去噪负样本**：  
  使用一个**重排器**或更强模型对难负样本进行过滤，去掉可能是假阴性的样本。  
  具体做法通常是：先用检索器挖掘难负样本，再用重排器判断哪些负样本“足够负”，或者把重排器得分高的负样本剔除/降权。

- **检索器与重排器迭代训练**：  
  先训练检索器，再训练重排器；然后用重排器帮助检索器筛选负样本；反复迭代。  
  这样负样本质量逐步提高。

- **数据增强/伪标签**：  
  RocketQA 还使用未标注问题生成伪正例/伪负例，扩大训练数据。具体细节我记不精确，但核心是“用重排器去噪”。

### 3. 与 ANCE 的区别
| 方面 | ANCE | RocketQA |
|---|---|---|
| 负样本来源 | 全局 ANN top-k | 全局 ANN + cross-batch |
| 假阴性处理 | 基本没有显式处理 | 用重排器去噪 |
| 训练方式 | 单检索器对比学习 | 检索器-重排器迭代 |
| 负样本规模 | 受 ANN top-k 限制 | cross-batch 扩大 |
| 核心贡献 | 动态难负样本 | 去噪难负样本 + 跨批次 |
