# E2 · b0 · round 1

ANCE 如何刷新全局难负例所用的 ANN 索引？

---

在 ANCE（Approximate Nearest Neighbor Negative Contrastive Estimation）里，**全局难负例**不是固定从某个静态负例池里采样，而是通过**周期性地用当前模型重新编码全量/大规模候选文档，并重建 ANN 索引**来刷新。这样，随着训练推进，模型表示空间变化，ANN 检索出来的“近似最近邻”也会变化，从而不断产生新的、更难的负例。

具体机制可以拆成下面几步：

1. **初始阶段**
   - 先用某个初始模型（通常是 BM25 热启动的 dense retriever，或预训练 dual-encoder）对文档集合编码。
   - 用这些文档向量构建一个 ANN 索引，例如 FAISS 索引。
   - 训练时，对每个 query 用当前 query 编码去 ANN 索引里检索 top-k 文档，作为候选负例；其中通常排除正例，再从中选难负例。

2. **训练过程中的刷新触发**
   - ANCE 不会每个 batch 都重建全库索引，因为代价太高。
   - 它按一定间隔刷新，例如每隔若干训练步、每个 epoch，或当模型更新到一定程度后。
   - 刷新的核心是：**用当前最新的 query encoder 和 document encoder 重新编码文档集合**，而不是继续用旧模型生成的文档向量。

3. **重新编码文档**
   - 对全量候选文档（corpus）用当前 document encoder 前向计算，得到新的 document embeddings。
   - 如果文档库很大，这一步通常需要分布式/多 GPU 推理，并可能用低精度或分片来加速。
   - 注意：ANCE 训练中 query encoder 和 document encoder 通常是共享或对称的 dual-encoder；刷新索引时要用当前用于检索的那一侧编码器。

4. **重建 ANN 索引**
   - 用新得到的 document embeddings 重新构建 ANN 索引。
   - 常见实现是 FAISS，例如 IVF-Flat、IVF-PQ、HNSW 等。
   - 重建后，后续训练 step 中的难负例检索就基于这个新索引进行。

5. **用新索引继续采样全局难负例**
   - 对每个训练 query，用当前 query encoder 编码后，在新 ANN 索引中检索 top-k 文档。
   - 这些文档作为候选，再按分数选择难负例：通常取分数较高但不是正例的文档。
   - 由于索引已经用新模型刷新，检索到的负例更接近当前模型认为的“难”负例，而不是旧模型认为的难负例。

6. **为什么必须刷新**
   - 如果 ANN 索引长期不更新，它反映的是旧模型的表示空间。
   - 随着训练进行，旧索引里的“最近邻”可能已经不再难，甚至变成容易负例，导致负例质量下降。
   - 刷新索引相当于让负例采样分布跟上模型变化，这是 ANCE 相比静态负例采样更有效的关键之一。

7. **实现上的常见做法与不确定点**
   - 在原始 ANCE 论文和后续实现中，刷新频率、是否刷新全库、是否只刷新部分文档、是否异步刷新，可能因实现而异。
   - 有些实现会异步刷新：训练继续用旧索引，后台用最新 checkpoint 重建新索引，重建完成后切换。
   - 有些实现可能只对候选池或部分文档重建索引，而不是每次全量重建。
   - 具体到某个代码库（如 ANCE 官方实现、Tevatron、Pyserini 等），刷新策略可能不同；如果你问的是某个特定实现，需要看它的配置项，例如 `refresh_interval`、`index_dir`、`reindex` 等。

总结一句话：**ANCE 通过定期用当前模型重新编码文档并重建 ANN 索引，使全局难负例检索始终基于最新的表示空间，从而持续获得更难的负例。**
