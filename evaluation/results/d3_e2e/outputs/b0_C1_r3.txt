## 一、总体演进主线

一句话概括：

> DPR 确立了“双塔稠密检索 + 批内负样本”的基本范式；ANCE 指出批内负样本太容易，引入异步全库负样本与难负样本刷新；RocketQA 进一步系统化地处理“假阴性”和训练数据质量问题，用去噪、跨批次负样本、数据增强提升检索器；RocketQAv2 则把检索器与重排器联合训练，用重排器动态挖掘更难、更可靠的负样本，形成“检索-重排互相促进”的闭环。

更细的主线可以写成：

1. **DPR：批内负样本，简单高效，但负样本偏易。**
2. **ANCE：全库难负样本 + 异步索引刷新，提升区分能力，但计算与工程复杂。**
3. **RocketQA：跨批次负样本 + 去噪 + 数据增强，缓解假阴性和数据偏差。**
4. **RocketQAv2：联合训练检索器与重排器，用重排器提供更可靠监督，动态挖掘难负样本。**

核心矛盾始终是：

- 负样本太容易：模型学不到细粒度区分；
- 负样本太难或标错：把真相关文档当负样本，造成假阴性；
- 负样本越多越好，但显存、计算、索引刷新成本高；
- 检索器与重排器分开训练，目标不一致，重排器无法反哺检索器。

## 二、DPR：批内负样本范式

### 1. 背景
DPR 的目标是用双塔模型做开放域问答中的段落检索：

- 问题编码器：\(E_Q(q)\)
- 段落编码器：\(E_P(p)\)
- 相似度：内积或余弦相似度

训练目标是让正样本段落得分高于负样本段落。

### 2. 负样本策略
DPR 主要使用：

- **批内负样本**
- 有时加入 **BM25 难负样本**
- 每个问题通常配 1 个正样本，若干负样本

批内负样本的做法是：  
在一个 batch 中，对于某个问题 \(q_i\)，它的正段落是 \(p_i^+\)，而同一 batch 中其他问题的正段落 \(p_j^+\) 被当作 \(q_i\) 的负样本。

这相当于把 batch 内其他样本的正例“借来”当负例，因此不需要额外维护全库索引，训练效率高。

### 3. 优点
- 实现简单；
- 不需要频繁全库检索；
- 在开放域 QA 上显著优于 BM25 等稀疏检索；
- 奠定了后续稠密检索训练的基本框架。

### 4. 局限
- 批内负样本数量受 batch size 限制；
- 这些负样本通常来自不同主题，和当前问题差异大，属于“容易负样本”；
- 模型可能只学会粗粒度主题匹配，而不是细粒度相关性；
- 若加入 BM25 难负样本，又可能引入假阴性：BM25 高分但实际相关的段落被误当负样本。

### 5. 在主线中的位置
DPR 是起点：  
它证明了“双塔 + 对比学习 + 批内负样本”可行，但负样本质量不足成为后续改进的核心突破口。

## 三、ANCE：异步全库难负样本

### 1. 论文
Xiong et al., 2021, *Approximate Nearest Neighbor Negative Contrastive Learning for Dense Text Retrieval*。

### 2. 问题意识
ANCE 明确指出：

- 批内负样本与当前问题分布不匹配；
- 真正困难的是全库中与问题相似但不相关的文档；
- 如果只用批内负样本，模型学不到全局区分边界。

### 3. 负样本策略
ANCE 的核心是：

- 使用 **全库近似最近邻负样本**；
- 通过 ANN 索引，为每个问题检索出当前模型认为最相似的文档；
- 这些文档中，非正例的作为难负样本；
- 因为模型和索引会不断更新，所以采用 **异步索引刷新**：训练一段时间后，重新用新模型编码全库并重建 ANN 索引，再挖掘新的难负样本。

可以理解为：

1. 用当前模型对全库建 ANN 索引；
2. 对每个训练问题，检索 top-k 近似最近邻；
3. 去掉正例，剩下的作为负样本；
4. 训练模型；
5. 定期刷新索引，重新挖负样本。

### 4. 优点
- 负样本更接近真实检索分布；
- 比批内负样本更难，能显著提升检索器；
- 在相同数据下优于 DPR 和 BM25 负样本策略。

### 5. 局限
- 需要维护全库 ANN 索引；
- 索引刷新带来额外计算和工程复杂度；
- 仍可能挖到假阴性：全库中某些高分文档其实相关，但被当作负样本；
- 训练不稳定，难负样本可能造成崩溃或过拟合。

### 6. 在主线中的位置
ANCE 把负样本从“batch 内”推进到“全库近似最近邻”，是负样本策略的一次关键升级。  
但它也暴露了后续 RocketQA 要解决的问题：**难负样本中的假阴性和训练噪声**。

## 四、RocketQA：去噪、跨批次负样本与数据增强

### 1. 论文
Qu et al., 2021, *RocketQA: An Optimized Training Approach for Dense Passage Retrieval*。

### 2. 问题意识
RocketQA 关注的不只是“负样本难不难”，还包括：

- 训练数据中的假阴性；
- 批内负样本数量不足；
- 数据规模和质量限制；
- 检索器训练与真实检索场景不一致。

### 3. 负样本与训练策略
RocketQA 的主要改进包括：

#### （1）跨批次负样本
传统批内负样本只用一个 batch 内的其他正例。  
RocketQA 使用 **cross-batch negatives**：  
把多个 GPU、多个 batch 的负样本集中起来，扩大负样本池。

这样可以在不显著增加单卡显存的情况下，获得更多负样本。

#### （2）去噪负样本 / 假阴性处理
RocketQA 强调训练数据中可能存在：

- 标注不完整；
- 某些被当作负样本的段落其实相关；
- 难负样本中混有假阴性。

因此它采用去噪策略，例如：

- 用更强模型或人工规则过滤；
- 对负样本进行重新标注或筛选；
- 避免把高置信相关文档当作负样本。

具体实现细节我在这里不展开到每个超参数；如果需严格引用，建议查原文对应章节。

#### （3）数据增强
RocketQA 还通过数据增强提升训练数据规模和多样性，例如：

- 利用无标注问题生成伪标签；
- 用检索器挖掘更多候选；
- 用重排器或人工验证提升正样本质量。

#### （4）训练目标
仍然是对比学习，但负样本来源更丰富、更干净。

### 4. 优点
- 跨批次负样本提升负样本数量；
- 去噪缓解假阴性；
- 数据增强提升泛化；
- 在 MS MARCO、Natural Questions 等任务上显著优于 DPR/ANCE。

### 5. 局限
- 训练流程更复杂；
- 去噪和数据增强依赖额外模型或标注；
- 检索器与重排器仍可能分开训练，尚未完全联合
